# （一）我们的群岛（Our Archipelago）

## 1 概述

### 1.1 一句话概念

每个人是一座岛。群里的人组成一片群岛；人与人之间的互动，成为岛间的桥、航线和共同地标。最终呈现为一张可以回看的「关系海图」。

### 1.2 面向谁、用在什么时候

面向愿意一起回顾经历的朋友群、班级群、社团或团队。用户主动提供一段群聊记录和共享相册，系统生成海图，适合聚会回顾、阶段总结和现场演示。它回答三个问题：这段时间谁在场、我们怎样联系、哪些时刻被大家共同经历。

### 1.3 整体逻辑

**提供群数据 → 识别成员、互动与共同经历 → 生成关系海图 → 点开个人和回忆 → 切换时间，看关系如何变化。**

海图展示的是所选数据和时间范围内留下的痕迹。它提供回忆的入口，不给任何人的性格或关系下定论。

## 2 需求分析：数据如何变成海图

### 2.1 数据入口

| 数据 | 用来发现什么 | 首版处理方式 |
| --- | --- | --- |
| 群聊记录 | 成员、发言频次、活跃时段、高频词，以及回复、提及等互动 | 用户主动导入，作为成图主数据 |
| 共享相册 | 同一时刻的照片、照片中可确认的参与者 | 用户主动导入，并确认共同经历 |
| 共同活动记录 | 旅行、聚会等事件的时间、名称和参与者 | 可补充；缺少时由用户手动添加 |
| 群成员画像 | 昵称、头像、自我介绍及愿意公开的角色描述 | 可补充；不强制填写 |

导入后先让用户核对成员身份与资料范围，再生成海图。同一人使用多个昵称时，允许手动合并；无法确认是谁的记录先不归到某座岛。

### 2.2 海图上的元素

每个元素都要能解释「为什么这样画」，点开后也要有对应内容。

| 元素 | 数据依据与画面含义 | 点击后看到什么 |
| --- | --- | --- |
| **一人一岛** | 一名确认的群成员对应一座独立岛屿。岛屿地形用来表达其在这段群聊中的参与方式，例如常张罗活动的火山岛、交流温和的森林岛、常提供可靠帮助的岩岛／灯塔岛、记录较少的远海孤礁。角色只是可调整的视觉比喻。 | 进入「岛屿档案」，查看发言时段、常用词、与谁互动，以及共同出现的照片和活动。本人可调整岛屿称呼。 |
| **桥梁** | 所选时间内两人持续、较频繁地直接互动，表示稳定往来。 | 查看这段连接的互动概览与相关共同经历。 |
| **航线／渡轮** | 两人有互动，但次数较少或不连续；航迹表达往来轨迹。 | 查看互动发生在哪些时段，并可进入相关回忆。 |
| **无连接** | 当前数据里缺少足够的直接互动依据。画面保留两座岛，不画连接。 | 仍可分别进入两人的档案；不显示「关系差」之类的判断。 |
| **共同地标** | 经参与者确认的一次共同旅行或事件，在所有参与者的岛上出现同一座山、同一片湖等同名地标。 | 显示共有几人、具体是谁、事件时间，以及关联照片和文字，供大家回看「谁还记得这一刻」。 |
| **灯塔** | 所选时间内常组织活动、连接多名成员的人，可在其岛上显示灯塔。 | 查看形成这一表现的活动或互动依据。 |
| **环礁** | 若几位成员之间经常彼此互动，可用环礁圈出这组岛。 | 查看小圈子的成员与共同活动；不把未圈入的人标为局外人。 |
| **雾与被淹的连接** | 最近在所选时间内少有记录的岛起雾；长时间没有新互动的桥或航线逐渐淡去，像被海水淹没。历史记录仍可回看。 | 查看最近一次有记录的时间，或切换时间窗口看过去的样子。 |

连接强弱主要参考两人之间的直接互动是否**双向、频繁、持续**；共同活动可以补充背景。具体画面随时间窗口重新计算，不能把消息量直接等同于亲密程度。数据少时宁可显示「依据不足」，也不硬选岛屿角色或画出桥梁。

### 2.3 时间视角

海图配一枚罗盘，切换「近一年」和「全部」。切换后，岛屿状态、桥梁、航线、灯塔、环礁和雾同步变化；共同地标按事件发生时间显示。用户可以看出关系如何生长、暂时安静或再次出现，而不是只看一张静态合照。

## 3 使用流程：从俯瞰到回忆

1. **提供数据。** 用户选择一个自己愿意提供的群，导入群聊和共享相册，核对成员与资料范围；系统不自行抓取其他群或私人资料。
2. **俯瞰群岛。** 首屏展示完整关系海图。先看每个人的岛，再看桥、航线、灯塔和环礁；图例用一句话解释每种符号。
3. **进入岛屿档案。** 点一座岛，看到这个人在当前时间范围内的发言习惯、常用词、主要互动对象，以及与其他人共同出现的照片。可返回海图继续探索。
4. **回看共同地标。** 点一处地标，看到事件、共享人数、参与者和相关照片；参与者确认后，地标才会出现在各自岛上。
5. **转动罗盘。** 在「近一年／全部」之间切换，对照哪些连接生长、淡去，哪些回忆一直留在岛上。

## 4 首版落地与演示

### 4.1 最小可演示版本

先用一份获得提供者许可的群聊记录和共享相册，完成**成员岛屿、三档连接、岛屿档案、共同地标、两档时间切换**。火山、森林等地形可以先采用简单插画或图标；灯塔、环礁、雾和航迹在有足够依据时展示。演示按上一节五步走，让观众从整片海图进入一段真实的共同回忆。

### 4.2 数据不足时

- 只有群聊：仍可生成岛屿和互动连接；共同地标由用户手动添加并确认参与者。
- 只有相册或记录很少：先展示成员与已确认的事件，不推断连接强度或岛屿角色。
- 照片不能确认参与者：不自动把照片归到某人的岛上，允许用户补充或跳过。
- 某人近期没有发言：可以起雾，但档案仍能查看历史；不把「潜水」解释成不在乎群体。

### 4.3 数据使用边界

只处理用户主动提供且有权分享的群资料。导入前明确说明将使用哪些内容、会向谁展示；成员可更正自己的身份、岛屿称呼和共同地标。展示照片与聊天片段时保留必要的查看范围，演示优先使用已获同意或脱敏的素材。

## 5 体验目标与验收

希望用户从「大家是一张联系人名单」走到「我们是一片一起经历过事情的群岛」。有时最打动人的画面是：**「原来在这群人眼里，我是一座正在起雾的岛。」** 随后的档案与时间切换，要让用户看见这只是近期记录变少，而过去的桥和地标仍在那里。

首版验收时，检查三件事：一是每名已确认成员都只有一座岛；二是任一桥、航线、地标或雾都能说明依据并进入对应内容；三是切换时间后画面与档案口径一致。若数据不足，界面应直说「依据不足」，不制造亲疏结论。
